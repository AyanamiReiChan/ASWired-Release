# 网站管理升级备份

v1.0.9 在「系统设置 → 系统维护」和「系统设置 → 备份与恢复」提供升级备份列表。正式组合包自更新后可直接使用；首次进入页面会刷新列表，处理中的请求会短暂轮询，完成后停止。

列表显示备份创建时间、升级前版本、文件名称与大小、占用空间及是否可删除。它识别安装器原来生成的 `/var/backups/aswired/YYYYmmddTHHMMSSZ` 目录，已有备份无需复制或转换。

单次最多显示最早的 1000 份备份；超过时会提示尚未列出的数量，合计大小只计算当前列表。清理旧备份后刷新即可继续查看。

删除前会显示所选备份，并要求输入完整备份标识确认。请求提交后，等待页面显示操作完成。删除会永久移除这一份升级备份；删除前应确认不再需要它恢复升级前的数据和配置。系统升级进行中会拒绝删除，目录异常时会显示不可删除及原因。

升级备份通常包含 `data.tar.gz`、`config.tar.gz` 和 `previous-release`；按文档执行的 PostgreSQL 手动升级还可能包含 `postgres-backup`。这些文件包含主控、Komari 的数据和系统配置，与网站创建的逻辑 ZIP 备份格式不同。本页面提供查看和删除；恢复升级前的数据仍按 [升级与恢复文档](UPGRADE.md) 执行。

## 权限与安装兼容

备份归档继续仅由 root 管理。网站只读取受限的元数据，管理员网页会话可提交刷新或删除请求；独立的 `aswired-upgrade-backups.path/service` 执行限定操作，不能接收任意路径或 shell 命令。API 令牌和普通成员不能操作升级备份。

新安装和网页自更新都会带上所需服务。主控启动依赖会启动新的 path 单元，兼容由旧版更新脚本完成的首次升级。非正式组合安装或管理服务未启动时，网页会显示不支持的原因。

备份列表不读取归档内容。删除校验备份根目录、备份标识和固定文件集合，不跟随符号链接，不递归删除任意目录，并与更新脚本共用锁。失败时查看网页状态与 `aswired-upgrade-backups.service` 日志，修正后重新刷新。
