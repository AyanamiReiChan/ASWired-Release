# 共享流量池套餐

共享流量池让同一套餐的所有成员共同使用一份流量额度。套餐设置的「总额度」就是整个池的额度，不会按成员人数增加。原有套餐可以直接编辑为共享类型，不需要重新分配套餐或重建订阅链接。

本功能需要升级主控和网站。已有套餐升级后仍按原来的独立额度运行，管理员手动改为「共享流量池」后才生效。本次没有修改远端 Agent 源码，无需为共享池单独升级远端 Agent。

## 额度如何计算

例如套餐的共享池总额度为 **100 GB**，Alice 本期已用 **30 GB**，Bob 本期已用 **20 GB**，共享池已用就是 **50 GB**，全体成员还可共同使用 **50 GB**。后续无论谁再使用 10 GB，池的共同余额都会变为 40 GB。

- 「共享池已用」和「共享剩余」反映整个套餐的使用情况。
- 「本人本期已用」或「此成员本期已用」仍反映该订阅实例的个人用量。个人周期与共享池周期可能不同，不能把页面上重复显示的池总量再次相加。
- 池总额度设为 `0` 表示不限流量。新增一个成员不会额外赠送一份池额度。
- 网站额度字段沿用现有 GB 标识，实际按 `1024³` 字节换算。

共享池累计的是现有流量台账中的**计费用量**。服务器、入站、套餐节点倍率及套餐的流量统计倍率仍按原规则生效；修改倍率只影响后续上报，不会重新折算历史用量。套餐里的节点单独额度仍按每位成员计算，不会变成共享节点额度。

## 将已有套餐改为共享池

1. 升级主控与网站后，用管理员账户打开「套餐」页面，编辑目标套餐。
2. 将「套餐流量类型」改为「共享流量池 · 全体成员共同使用」。
3. 填写「共享池总额度（GB）」，检查重置策略、重置日期或计量周期。
4. 在「更多设置」检查额度耗尽后的套餐策略：停止服务，或按套餐设定速度限速。
5. 保存后核对套餐卡片和成员订阅中的共享池已用、共同余额、实例数量及统一重置时间。

首次切换会计入现有成员**各自本账期已经使用的流量**，不会从零开始。若已用合计达到或超过新设的池总额度，保存后全体成员即适用该套餐的额度耗尽策略。订阅实例原有的个人额度和个人超额设置会被保留，但共享期间使用套餐的池总额度与统一超额策略。

新建套餐也可以直接选择共享流量池；没有成员消费时，池已用为零。

## 首期与后续重置

已有成员的个人账期可能不同。首次转换时，系统分别保留每个实例当时的本期起点，汇总其本期用量；不会用最早一个人的起点重新计算所有人，也不会遗漏转换前的本期消费。

共享池的下一次重置由套餐策略统一确定：

| 套餐重置策略 | 共享池的重置方式 |
| --- | --- |
| 每月指定日 | 按套餐选定日期和时区统一重置；当月没有该日期时使用当月最后一天 |
| 按计量周期 | 首期从首次启用共享池的时刻起，按套餐设置的天数确定下一次重置 |
| 不重置 | 持续累计，不自动恢复池余额 |

首次统一重置后，所有池成员都按同一个共享周期累计。个人订阅的有效期和个人用量展示仍保留各自规则；某个人的个人账期更新不会清空共享池。

编辑套餐重置策略会调整共享池后续重置时间，不会因为一次普通编辑而清空尚未结束的池周期。已经到达的统一周期边界仍按重置规则处理。共享套餐不能使用「单独重置成员流量」来恢复池额度。

## 成员变化与额度耗尽

| 操作 | 对共享池的影响 |
| --- | --- |
| 新增成员或分配实例 | 加入当前池并共同使用剩余余额；不增加总额度，不重置池 |
| 续期 | 延长订阅有效期；不清空已用流量 |
| 停用、到期、删除成员或删除订阅实例 | 停止相应权限后，已经产生的本期池消费仍然保留，不退还余额 |
| 调整池总额度 | 保留已用量，按新额度判断是否继续服务；增额可以解除因池耗尽产生的限制 |
| 改回独立额度 | 恢复各实例原有的个人额度和超额设置；保留池的计量状态 |
| 再次改回共享池 | 在同一池周期内继续累计，不靠切换类型清零；独立期间该周期内的消费也会计入，已正常经过的统一周期边界仍会重置 |

额度耗尽时，全体池成员在本套餐中按**套餐统一设置**停止服务或超额限速；旧实例的个人不限额、个人超额策略不能绕过共享池。主控依据收到的流量上报进行判断，并通过现有维护及下发流程同步所有受影响成员，执行结果以 Agent 回报为准。成员停用、订阅到期和节点权限等原有条件仍然生效。

普通订阅、生成订阅及临时订阅的客户端流量信息均使用池的总用量和总额度。网站同时保留个人用量展示。普通成员只能看到池的聚合统计和自己的订阅信息，不能据此获取其他成员的订阅凭据或计费明细。

## 数据、备份与版本兼容

共享池沿用原始流量台账，并另外保存统一周期及成员计费窗口。重置、成员离开或切换类型不会删除原始流量记录。统计缓存可以依据台账重建，不能通过删除数据库、台账或池状态来处理余额问题。

网站创建的完整应用备份包含共享池状态与流量台账；恢复时应使用支持共享池的主控版本，并一起保留账户、配置、密钥和计费数据。正式组合安装的升级前备份仍由原升级流程创建，网站中可按 [升级备份管理说明](UPGRADE-BACKUPS.md) 查看和管理。外部 PostgreSQL 还须按 [升级文档](UPGRADE.md) 备份实际使用的数据库，服务器文件归档不能代替外部数据库备份。

**启用共享池后，不可直接切回不支持共享池的旧版程序。**旧版会忽略共享模式，继续按实例的个人额度放行，不能正确执行共同余额限制。站内自更新只接受更新版本，但手工切换旧程序仍有此兼容问题。

如升级后遇到故障，应保留最新数据库、台账、密钥和日志，优先使用支持共享池的修复版本。需要设计回退方案时，应先停止新增业务写入、备份当前完整状态，并核对套餐权限和账务迁移方式；不能仅替换旧程序，也不能为回退程序而恢复旧数据库、丢弃升级后的新增流量。升级备份用于受控恢复和核查，不是重置消费的方式。
