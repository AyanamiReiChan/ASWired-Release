# 主控和 Komari 网站证书

v1.0.5 的「证书管理」同时显示本机主控网站、Komari 正在使用的 HTTPS 证书，以及主控申请或上传的证书记录。实际状态通过本机 HTTPS 握手、域名和系统信任链校验取得；证书记录存在、部署请求排队都不等于网站已生效。

## 已有 HTTPS 的部署

升级默认开启「外部已配 HTTPS/反代」。进入页面或升级本身不会切换证书。已有 Caddy 自动签发与续期继续运行，页面显示其颁发机构、到期时间、管理者和续期状态。

网站自动部署目前支持正式 Linux 组合安装上的本机标准 Caddy：`/usr/bin/caddy`、`caddy` 服务用户、回环管理接口 `127.0.0.1:2019`。网站域名取自 root 管理的 `/etc/aswired/server.env`。Nginx、远端反代、自定义 TLS SNI/客户端认证匹配规则等不支持自动接管时，请保留外部模式。安装器默认 Nginx/Certbot 的新部署仍使用原有证书管理方式；此版本不会转换反代软件。

## 通过主控申请、续期和部署

1. 在「DNS 提供商」保存有权修改目标域名 DNS 验证记录的凭据。
2. 关闭「外部已配 HTTPS/反代」并确认。此操作只允许后续部署，尚不替换现有证书。
3. 申请证书，填写覆盖目标网站的域名；可勾选根域名与泛域名。泛域名必须使用 DNS-01，其他网站证书也推荐 DNS-01，避免与现有反代的 80 端口冲突。
4. 选择「Master · 主控网站」「Master · Komari」中的一个或两个，按需开启自动续期、自动部署。证书必须覆盖所有选定域名。
5. 签发后部署，等待「网站证书已实际生效」，并核对网站行和证书记录的「已生效」状态。部署服务校验证书链、域名、有效期、私钥匹配，热加载 Caddy 后再校验实际 HTTPS 指纹；失败会尝试恢复先前配置。

也可上传完整 PEM 证书链和私钥，随后选择部署目标。上传证书不能自动向 CA 续期，需要在过期前上传替换材料。测试 CA 和未被主机系统信任的自签名证书不能部署到网站。

自动续期和自动部署需要同时开启，续期后的材料才会自动切换到网站。网站行显示实际服务的证书；若新证书部署失败，旧证书仍可能有效，需查看部署错误并重新部署。正在被网站引用或尚在部署中的证书不能删除。

重新开启外部模式会排队撤回主控自己的证书绑定，保留网站路由和原有 TLS 设置，再检查 HTTPS。原本禁用的外部自动签发不会被擅自开启。返回外部模式后，Caddy 仍从持久化 JSON 启动；原 Caddyfile 保留为运维参考，不会自动重新导入其内容。

## 服务、备份与恢复

- `aswired-certificates.path` 监听部署请求，`aswired-certificates.service` 以 root 执行固定的证书操作；主控继续使用低权限账户。
- `/var/lib/aswired-certificates/` 保存部署状态、网站绑定、证书材料、Caddy JSON 和操作前备份。私钥仅 root 与 Caddy 可读，状态摘要可由主控读取。
- `/etc/systemd/system/caddy.service.d/90-aswired-certificates.conf` 指定持久化 JSON，确保重启仍使用已部署证书。成功后保存的备份位于 `backups/`；中断事务在服务退出或下次执行时尝试恢复。
- 排错使用 `journalctl -u aswired-certificates --no-pager`。恢复失败时保留事务日志；先修复 Caddy 可用性，再由管理员检查恢复备份。

这些反代状态与证书材料不在应用数据库备份内。接管后应另外安全备份 `/var/lib/aswired-certificates`、上述 Caddy drop-in、Caddy 配置和存储目录。保留文件所有权及权限，恢复时将材料和引用它的配置一起恢复。不要将备份上传到公开仓库。

从 v1.0.4 网页自动升级会安装新服务，并通过主控的 systemd 依赖启动证书请求监听器，无须手工部署证书服务。实际证书切换仍由管理员明确触发。
